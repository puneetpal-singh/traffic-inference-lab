Accuracy and latency

OpenVINO FP16 compresses stored constants; runtime precision is separately inspected. TensorRT FP16/INT8 enable mixed-precision tactics, so the engine may retain higher precision layers. ONNX profiles separately verify CUDA kernel placement. ONNX FP16 denotes the exported graph: CPU profiles show FP32 weighted-kernel inputs after runtime conversion. Strict box-level parity is recorded as a diagnostic; quantized models are judged on held-out mAP loss.

PyTorch uses four CPU threads. ONNX Runtime and OpenVINO use backend threading defaults; these are not equal-thread-budget tests.

Camera scaling, tracking and batching

24 serving experiments. Each camera replays the same clip at source FPS, has an independent tracker and a bounded queue, and requests one decoder thread. Model choices lose at most one absolute point of both global mAP and mean vehicle AP against the same-size CPU PyTorch baseline. Serving warms the detector with five zero-image calls and real first-frame batches before replay; trackers start fresh. The illustrative serving timing gate is at least 15 processed FPS and p95 frame age at most 100 ms for every camera.
